# Native Viewport and Geometry Migration

## Goal

Develop a separate Qt Quick 3D viewport foundation in small, reversible stages while keeping the Tauri workbench as Outlaw Forge's main desktop workflow. The Qt application in `apps/native/` is experimental and is not currently included in the Tauri package. No default-app cutover is scheduled; packaging or replacement requires demonstrated workflow parity and release validation.

The native renderer uses Qt Quick 3D. The project scene remains right-handed, Z-up, and measured in millimetres. Renderer-specific conversion belongs at the import/render boundary; it must not change stored project coordinates.

## Migration stages

1. **Scene and navigation - initial foundation implemented**: build plate, lighting, camera orbit, pan, zoom, presets, and orientation gizmo.
2. **Mesh lifecycle - initial foundation implemented**: local STL/OBJ and limited 3MF import; scene list, selection, frame, hide, and remove. Native service registration currently supports STL/OBJ only.
3. **Instance transforms - initial foundation implemented**: translate, rotate, scale, duplicate, and mirror using millimetre transforms in the in-memory scene.
4. **Inspection and display - initial foundation implemented**: wireframe, bounds, sampled normals, mesh analysis, and measurement. The current 3MF limitations remain documented below.
5. **Geometry operations - first command implemented**: planar slicing routes through the existing FastAPI project/import/slice/file endpoints for STL and OBJ. Move further operations one at a time while preserving parameters, provenance, source immutability, and regression behavior.
6. **Parity, persistence, and packaging - future work**: add project save/reopen and workflow acceptance, then evaluate Tauri integration only after feature coverage and release validation.

## Geometry command boundary

Each operation consumes a source revision identifier and a typed parameter object. It returns a new derived revision identifier, output metadata, and provenance. It never mutates `data/uploads/` or the input revision. Requests and responses must remain aligned with the Pydantic schemas in `apps/api` and TypeScript contracts in `packages/shared` until the API is intentionally retired.

The native viewport owns interaction and presentation. Geometry algorithms own deterministic mesh results. This boundary allows the UI to migrate before each algorithm and allows the existing FastAPI service to remain the operation provider during the transition. The selected-instance inspector reports a world-aligned axis bounding box by mapping all eight corners of the immutable source bounds through the active Qt Quick 3D transform; the reported values remain in millimetres and account for rotation and signed scale.

## Current slice

`apps/native/` currently contains a Qt Quick 3D scene with a millimetre build plate, grid, lighting, camera orbit/pan/zoom, Top/Front/Right/Isometric presets, Ctrl+1 through Ctrl+4 shortcuts, and a camera-tracking XYZ orientation gizmo with six axis-aligned snap views. It supports STL, OBJ, and limited 3MF import, scene selection, hide/show, remove, duplicate, reset transforms, non-destructive position, rotation, per-axis scale, and X/Y/Z mirror controls. Orca-style placement actions center the selected model's transformed XY bounds at the build plate origin and move its lowest transformed point to Z=0 mm; both actions are available from the inspector and model context menu. Scene entries are instances sharing mesh geometry; each instance stores its own transform and visibility in the current in-memory scene list. Mirror is represented as a negative scale on the chosen axis, so it does not alter imported source geometry. Ctrl+Shift+R resets selected model transforms, restores visibility, and frames it. OBJ faces are triangulated as a fan and support positive and relative negative vertex indices. The 3MF reader handles the first build item when it references a direct mesh object, applies the serialized affine transform, and converts recognized model units to millimetres; component graphs, multiple build items, materials, textures, colors, and slicer project metadata remain unsupported. Framing aims at the transformed model center, fits its bounds to the viewport including scale and window aspect ratio, and preserves current transforms. Inspection controls provide wireframe rendering, a cyan bounds outline, sampled face normals, mesh-health analysis, and two-point surface measurement. Measurement mode records two surface picks in scene millimetres, displays both endpoints as markers, and reports their Euclidean distance to three decimal places. Wireframe currently uses Qt Quick 3D scene debug settings, so it also affects the build plate and grid.

The first migrated geometry command is service-backed planar slicing for STL and OBJ. The native session lazily creates a FastAPI project, uploads an immutable source, maps the active world-space slice plane into source coordinates (including instance rotation, scale, translation, and reflection), and calls the existing project slice route with capping enabled and pegs disabled. Both persisted result models are downloaded to app-local derived storage before the scene changes. Keep-both mode shows each result as a distinct instance; either single-side mode displays the selected half and leaves both API records in project history. The viewport reports `is_watertight` for each half and never reports closure when a returned half is open. If service calls or downloads fail, the source remains visible and returned model IDs are included when available. 3MF remains viewable but cannot yet use service slicing. Mesh analysis and repair remain local operations. The API base URL defaults to `http://127.0.0.1:8000` and can be overridden with `OUTLAW_FORGE_API_URL`. Persistent project reopening, broader parity acceptance, packaging into the existing Tauri lifecycle, and migration of other geometry operations remain future work. The 3MF reader currently depends on Qt's private `QZipReader` API.

The native target requires Qt 6.6+, CMake 3.21+, and a C++20 compiler. Build instructions are in `apps/native/README.md`.
